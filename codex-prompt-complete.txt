## THE EXACT PROBLEM

Phantom's signMessage API intentionally rejects ANY input that could be structurally decoded as a Solana transaction, even if it is just a raw 32-byte SHA-256 hash digest. This is Phantom's documented anti-phishing security feature, not a bug. We have tested every possible variant (wallet adapter, window.phantom.solana.signMessage, Uint8Array, Buffer, ArrayBuffer, sliced, copied) and all fail with: "You cannot sign solana transactions using sign message".

Our old frontend had a hidden fallback: when Phantom failed, it called a backend API route that signed the digest using nacl.sign.detached with a local keypair. That is why old claims exist. The current frontend no longer has this fallback, so the flow is completely blocked.

## THE CORRECT PERMANENT SOLUTION (Delegated Signer Architecture)

We must separate "FID ownership" from "claim signing":

Layer 1 — Management/Authority (Phantom wallet)
- The KYC provider's Phantom wallet remains the FID owner and managementKey
- It pays transaction fees and signs on-chain transactions (AddClaim tx, rotateSignerKey tx)
- It NEVER signs raw claim digests

Layer 2 — Dedicated Claim Signer (Backend API)
- A stable Ed25519 keypair whose ONLY job is to sign claim digests
- Stored securely in environment variables (dev/testnet) or KMS (production)
- Exposed via an authenticated API endpoint: POST /api/provider/sign-claim
- Its public key is stored on-chain as the provider FID's signerKey

Layer 3 — On-Chain Verification
- The AddClaim instruction verifies: claim.signature.public_key == issuer_fid.signer_key
- Since signerKey now points to the backend signer, verification passes
- The Ed25519 verification instruction validates the signature cryptographically

## CRITICAL RULES (ABSOLUTE — DO NOT VIOLATE)

1. NO automatic signer rotation during KYC approval. Signer mode must be EXPLICIT.
2. NO silent fallback from wallet to backend. The system must DETECT which signer is configured and use ONLY that path.
3. NO wallet-switching hacks. Phantom is correct to block this. We architect around it.
4. If on-chain signerKey == connected wallet -> use wallet-backed signing (and show clear error if wallet refuses).
5. If on-chain signerKey == configured dev signer public key -> use the backend API route.
6. If neither matches -> show explicit error: "Current provider signer is not available. Connect the correct signer or configure explicit delegated/dev signer."
7. Signer rotation must ONLY happen through an explicit Identity Manager UI action, with a WARNING that it invalidates all previously issued claims.

### FILE 2: src/app/api/provider/sign-claim/route.ts (NEW)
A Next.js API route that signs claim digests using the dedicated backend keypair.

Use this exact code:
```typescript
import { NextRequest, NextResponse } from "next/server";
import nacl from "tweetnacl";
import bs58 from "bs58";

export async function POST(request: NextRequest) {
  try {
    const secretB58 = process.env.PROVIDER_CLAIM_SIGNER_SECRET;
    const publicB58 = process.env.PROVIDER_CLAIM_SIGNER_PUBLIC;

    if (!secretB58 || !publicB58) {
      return NextResponse.json(
        { error: "Provider claim signer not configured. Set PROVIDER_CLAIM_SIGNER_SECRET and PROVIDER_CLAIM_SIGNER_PUBLIC in .env.local" },
        { status: 500 }
      );
    }

    const body = await request.json();
    const { claimDigest } = body;

    if (!Array.isArray(claimDigest) || claimDigest.length !== 32) {
      return NextResponse.json(
        { error: "claimDigest must be an array of exactly 32 bytes" },
        { status: 400 }
      );
    }

    const secretKey = bs58.decode(secretB58);
    const digest = new Uint8Array(claimDigest);
    const signature = nacl.sign.detached(digest, secretKey);

    return NextResponse.json({
      signature: Array.from(signature),
      signerPublicKey: publicB58,
    });
  } catch (err) {
    console.error("[sign-claim] error:", err);
    return NextResponse.json(
      { error: err instanceof Error ? err.message : "Unknown error" },
      { status: 500 }
    );
  }
}
```

### FILE 3: src/services/claimSigner.ts (NEW)
A frontend helper that detects which signer mode to use and executes the correct signing path.

Use this exact code:
```typescript
import { PublicKey } from "@solana/web3.js";

const DEV_SIGNER_PUBLIC = process.env.NEXT_PUBLIC_PROVIDER_CLAIM_SIGNER_PUBLIC;

export type SignerMode = "wallet" | "dev-backend" | "unknown";

export interface ClaimSignatureResult {
  signature: Uint8Array;
  signerPublicKey: string;
  mode: SignerMode;
}

export function detectSignerMode(
  onChainSignerKey: PublicKey,
  connectedWallet: PublicKey
): SignerMode {
  const onChain = onChainSignerKey.toBase58();
  const wallet = connectedWallet.toBase58();

  if (onChain === wallet) return "wallet";
  if (DEV_SIGNER_PUBLIC && onChain === DEV_SIGNER_PUBLIC) return "dev-backend";
  return "unknown";
}

export async function signWithWallet(
  walletAdapter: any,
  digest: Uint8Array
): Promise<ClaimSignatureResult> {
  if (!walletAdapter.signMessage) {
    throw new Error("Wallet does not support signMessage.");
  }
  try {
    const signature = await walletAdapter.signMessage(digest);
    return {
      signature: new Uint8Array(signature),
      signerPublicKey: walletAdapter.publicKey.toBase58(),
      mode: "wallet",
    };
  } catch (err: any) {
    if (err.message?.includes("You cannot sign solana transactions using sign message")) {
      throw new Error(
        "Phantom refuses to sign this claim digest. " +
        "Please rotate your provider FID signerKey to the dev backend signer in Identity Manager."
      );
    }
    throw err;
  }
}

export async function signWithBackend(digest: Uint8Array): Promise<ClaimSignatureResult> {
  if (!DEV_SIGNER_PUBLIC) {
    throw new Error("Dev backend signer not configured.");
  }
  const res = await fetch("/api/provider/sign-claim", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ claimDigest: Array.from(digest) }),
  });
  if (!res.ok) {
    const err = await res.json();
    throw new Error(err.error || "Backend signing failed");
  }
  const data = await res.json();
  return {
    signature: new Uint8Array(data.signature),
    signerPublicKey: data.signerPublicKey,
    mode: "dev-backend",
  };
}

export async function signClaimDigest(
  walletAdapter: any,
  onChainSignerKey: PublicKey,
  digest: Uint8Array
): Promise<ClaimSignatureResult> {
  const mode = detectSignerMode(onChainSignerKey, walletAdapter.publicKey);

  if (mode === "wallet") return signWithWallet(walletAdapter, digest);
  if (mode === "dev-backend") return signWithBackend(digest);

  throw new Error(
    `Signer mismatch.\n` +
    `On-chain signerKey: ${onChainSignerKey.toBase58()}\n` +
    `Connected wallet:   ${walletAdapter.publicKey.toBase58()}\n` +
    `Configured dev signer: ${DEV_SIGNER_PUBLIC || "(not set)"}\n\n` +
    `To fix: rotate provider FID signerKey to either your connected wallet or the dev signer in Identity Manager.`
  );
}
```
